# Capture everything verbatim, distil nothing as fact

**The evidence favours one design: record every session event verbatim and deterministically, add derived and LLM-written structure only as labelled, invalidatable indexes over that record, and give the next model a short brief with fixed sections plus ID-addressable drill-down instead of a summary.** Across LongMemEval, LoCoMo, MemoryAgentBench and DMR, the systems that replace history with LLM-extracted facts or summaries consistently score below systems that read the raw history. ChatGPT memory scored 37% below offline reading of the same history, and recursive summaries answered about 35% of DMR questions against 93% for lossless paging ([LongMemEval](https://arxiv.org/abs/2410.10813); [MemGPT](https://arxiv.org/abs/2310.08560)). Coding agents add a sharper problem. The strongest graph memory measured, Zep, was **17.7 points worse than full context at recalling what the assistant itself did** ([Zep paper](https://arxiv.org/html/2501.13956v1)), and "what the agent did" is most of what a coding handoff carries. Continuum's founding choices (append-only PostgreSQL journal, verbatim user words, no LLM, runtime-observed facts, human-registered checks) match this evidence better than any vendor memory product examined. Its main weakness is not how it remembers but what it never records. It keeps each tool call as a one-line action with a failed flag, and throws away tool results, command output, before/after file impact, pre-call intent, subagent work and compaction events. Every major app now exposes these through hooks or transcripts. The priority is therefore to widen deterministic capture (tool lifecycle with unknown-outcome detection, file impact, redacted output blobs, sidechains), to make supersession explicit, and to upgrade recall. An optional LLM extractor comes last, and only as claims with provenance.

## Verbatim capture beats LLM extraction on every measured axis except token cost

The measured trade-off is lopsided. The base Mem0 paper itself shows **full context at 72.9% on LoCoMo against 66.9% for Mem0 and 68.4% for its graph variant**. Memory wins only on cost and latency: about 1.8k–3.6k tokens and 1.4–2.6 s p95, against about 26k tokens and 17 s ([Mem0 paper](https://arxiv.org/abs/2504.19413)). MemoryAgentBench found that Mem0 and Cognee score far *below their own backbone model* on short-context retrieval and in-context learning: Mem0 got 31/25/25 on single-hop QA where GPT-4o-mini alone scored 84/83/64. The same benchmark found that these systems "need extremely high resources when constructing the memory" ([MemoryAgentBench](https://arxiv.org/abs/2507.05257)). LongMemEval's ablations isolate the cause. Replacing rounds or sessions with extracted facts or summaries "negatively impacts QA performance due to information loss". Session summaries used as retrieval keys dropped GPT-4o's top-10 QA from 0.676 to 0.252 ([LongMemEval](https://arxiv.org/abs/2410.10813)). A 2026 preprint states the principle directly: "content discarded before the query is known cannot be recovered at retrieval time" ([Storage Is Not Memory](https://arxiv.org/abs/2605.04897)).

LLM extraction fails in recognisable, well-documented ways. LoCoMo's error analysis of incremental summaries found **hallucinated details padded from other events and wrong speaker attribution**, with the best event-summary FactScore F1 at about 45.9 ([LoCoMo](https://arxiv.org/abs/2402.17753)). The SSGM governance paper calls the mechanism semantic drift: "I like mild spicy food" becomes "loves very spicy food" after re-encoding. Its proposed remedy is reconciliation against an **immutable episodic ledger** ([SSGM](https://arxiv.org/html/2603.11768v1)). ChatGPT's memory "tended to overwrite crucial information as the chat continues" ([LongMemEval](https://arxiv.org/abs/2410.10813)). Base Mem0 *deletes* conflicting facts and lets callers overwrite memory text in place ([Mem0 paper](https://arxiv.org/html/2504.19413v1); [Mem0 docs](https://docs.mem0.ai/core-concepts/memory-operations/update)). A-MEM's "memory evolution" rewrites older notes when new ones arrive ([A-MEM](https://arxiv.org/html/2502.12110v8)). Each of these destroys the provenance an audit-grade continuity layer needs.

Agent trajectories add evidence of their own. In JetBrains' Complexity Trap study (SWE-agent, SWE-bench Verified, n=500), **simple observation masking matched or beat LLM summarization at equal or lower cost**. With Gemini 2.5 Flash in thinking mode, LLM summary dropped the solve rate to 31.4% against 40.4% for the raw agent, a significant loss. Summaries also lengthened trajectories by 13–15%, which the authors attribute to summaries "mask[ing] failure signals that would otherwise prompt earlier termination" ([Complexity Trap](https://arxiv.org/abs/2508.21433)). ACON shows that task-optimized compression can stay close to uncompressed accuracy with 26–54% lower peak tokens. The same paper shows naive prompted *observation* compression collapsing OfficeBench accuracy from 76.8% to 55.8%, and warns that "over-compression may remove subtle facts needed for final decisions" ([ACON](https://arxiv.org/abs/2510.00615)).

LLM extraction does help in two narrow places. Extracted facts work well as **additional index keys** alongside the raw text: keys made of the value plus its extracted facts raised recall@k by 9.4% and QA by 5.4% on average, whereas facts as the *only* key were worse than the raw text ([LongMemEval](https://arxiv.org/abs/2410.10813)). Fact decomposition also helps multi-session aggregation. That defines the only safe role for an LLM in Continuum: an optional index-builder and claim-proposer whose output never replaces the record and never enters the brief as fact. Provenance makes this enforceable. Zep/Graphiti is the one production system that keeps non-lossy raw episodes with **bidirectional fact-to-episode indices** ([Zep paper](https://arxiv.org/html/2501.13956v1)). The same pattern lets Continuum attach `source_event_ids`, extractor model, prompt hash and timestamp to every derived item.

How much to trust this evidence: every benchmark above is conversational QA about personal facts, not coding handoff. LoCoMo numbers for the same system vary by 5–30 points between harnesses: Zep has been reported at 58%, 66%, 75% and 94.7% ([zep-papers #5](https://github.com/getzep/zep-papers/issues/5); [Mem0 comparison](https://mem0.ai/library/agent-memory/zep-vs-mem0-which-ai-memory-layer-should-you-choose); [Zep research](https://www.getzep.com/research/)). The direction of the extraction-vs-verbatim result holds across independent benchmarks. The size of any single number does not.

## Four memory types, one immutable source, and supersession instead of deletion

Surveys and recent systems converge on separating memory by function. The Dec 2025 survey divides it into factual and experiential memory ([survey](https://arxiv.org/abs/2512.13564)). Zep splits episodic, semantic and community subgraphs ([Zep paper](https://arxiv.org/html/2501.13956v1)). ENGRAM reports gains from typed episodic, semantic and procedural records ([ENGRAM](https://arxiv.org/abs/2511.12960)). The only coding-specific ablation found that both kinds help and work best together: on a SWE-Bench Pro subset, Exp-SWE-Agent rose from 42.7% to 47.5% with factual plus experiential memory, against 43.1% and 44.1% for each alone ([Exp-SWE-Agent](https://dl.acm.org/doi/pdf/10.1145/3803437.3807663)). Procedural memory as workflows induced from trajectories gave +51.1% relative success on WebArena ([AWM](https://proceedings.mlr.press/v267/wang25bx.html)). Mapped to Continuum, the episodic layer is the event journal. The semantic layer is requirements, decisions and constraints. The procedural layer is repo know-how: build and test commands that worked, and approaches that failed. Within one task, episodic and semantic memory carry most of the value. Procedural memory pays off across tasks.

Contradiction handling is the weakest ability in every benchmark, and that justifies making it a runtime responsibility rather than leaving it to model judgment. On MemoryAgentBench's multi-hop fact consolidation, **"all methods fail… achieving at most 28% accuracy"** ([MemoryAgentBench](https://arxiv.org/abs/2507.05257)). BEAM's contradiction-resolution scores sit at about 0.00–0.05 for long-context, RAG and structured baselines alike ([BEAM](https://arxiv.org/abs/2510.27246)). EverMemBench finds that "temporal reasoning fails without explicit version semantics beyond timestamps" ([EverMemBench](https://arxiv.org/abs/2602.01313)). MemoryLACE, which models explicit merge, supersession and contradiction relations with provenance, credits "lifecycle expansion and temporal awareness" as its main contributors ([MemoryLACE](https://arxiv.org/abs/2609.03201)). Zep's bi-temporal model gives a working template. Each fact has a valid interval (`t_valid`/`t_invalid`) and a system interval (`t'_created`/`t'_expired`). A contradicting edge *invalidates* the older one without deleting it ([Zep paper](https://arxiv.org/html/2501.13956v1)).

For Continuum, supersession should be a derived record in a projection that can be rebuilt, never a mutation of history. Each requirement or decision carries `valid_from`, `recorded_at`, `superseded_by`, `source_event_ids` and an **authority** field. The authority values are user, human operator, runtime observation, agent claim, and untrusted tool output. Zep's "new information wins" rule should apply only within or above the same authority. A later agent sentence must never silently supersede a user requirement *(inference)*. The brief should show a superseded requirement either not at all or explicitly marked as superseded, with the replacing message number. Chroma found that near-miss distractors cause confident hallucination, especially in GPT-family models ([Chroma Context Rot](https://research.trychroma.com/context-rot)). A graph store is unnecessary. PostgreSQL rows with `superseded_by` and `wasDerivedFrom`-style foreign keys express the PROV relations (`used`, `wasGeneratedBy`, `wasAssociatedWith`) that PROV-AGENT applies to AI agents ([W3C PROV-O](https://www.w3.org/TR/prov-o/); [PROV-AGENT](https://arxiv.org/html/2508.02866v1)). Mem0 measured Zep's graph at over 600k tokens, with duplicated nodes and background lag before memory became usable ([Mem0 paper](https://arxiv.org/html/2504.19413v1)), which is a cost Continuum does not need to pay.

## A short fixed brief for must-know state, retrieval by ID for everything else

The question is not retrieval *versus* brief; each covers a different failure. Context length itself costs accuracy. GPT-4o fell from 0.870 with only the evidence sessions to 0.606 with the full ~115k history, and Llama 3.1 70B lost 55% ([LongMemEval](https://arxiv.org/abs/2410.10813)). Chroma found that a focused ~300-token prompt significantly beat the same content in ~113k tokens for the Claude, GPT, Gemini and Qwen families ([Chroma](https://research.trychroma.com/context-rot)). Position matters too. Lost-in-the-middle found a U-shaped curve: GPT-3.5-Turbo scored 75.8% with the answer first and 53.8% with it in the middle ([Liu et al.](https://arxiv.org/abs/2307.03172)). Retrieval, however, captures "only partial information… lacking the ability to capture a holistic understanding", and long-context reading wins on long-range understanding ([MemoryAgentBench](https://arxiv.org/abs/2507.05257)). So the state a model *must* have (open requirements, unresolved effects, failing checks, the next action) cannot depend on the model choosing to search. It belongs in a fixed brief. Everything else should be one ID away.

Vendors arrive at the same split. Anthropic recommends "the smallest possible set of high-signal tokens", lightweight identifiers for just-in-time loading, and tool-result clearing as "the safest lightest touch form of compaction" ([Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Manus keeps compression "restorable" by preserving URLs and paths, treats the file system as context, and deliberately leaves "the wrong turns in the context" ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). Cognition argues that "actions carry implicit decisions" and that agents should share full traces, not single messages ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)). The tension between distilled summaries and full traces resolves into one design. The brief carries verified state plus decision records drawn from actions, and every line carries event IDs, so the receiving model can fetch the exact tool output, diff or message behind it.

The reading format and budget also matter. LongMemEval found that **reading strategy alone costs up to 10 points even with perfect recall**. JSON-structured items, sorted by time and read with Chain-of-Note, did best ([LongMemEval](https://arxiv.org/abs/2410.10813)). The retrieval budget depends on the reader: Llama 3.1 8B "drops sharply beyond 3k retrieved tokens" while GPT-4o kept improving past 20k (same source). That supports a **per-receiver token budget that rejects an oversize packet instead of truncating it**, which is Continuum invariant 9. Manus's cache economics favour a stable, deterministic prefix with volatile state last: cached input is 10× cheaper ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). Anthropic's harness work adds that agents "declare the job done" after seeing partial progress. Its remedy is JSON feature lists in which only a `passes` field may change, set after end-to-end verification ([Anthropic harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). This directly supports Continuum's verifier-gated tasks.

Continuum's current brief already follows much of this: an Attention section first, fixed caps with omissions counted, claims labelled, and text flattened so it cannot forge headings ([MEMORY-ALGORITHM.md](../docs/MEMORY-ALGORITHM.md)). Its internal benchmark reports **100% retention of planted requirements in chats of 10–160 messages at 0.7k–3k tokens**. Its trials report 13/13 and 7/7 with the brief against 9/13 and 4/7 without, for Haiku, Sonnet and Opus ([MEMORY-QUALITY.md](../docs/MEMORY-QUALITY.md)). These are strong but narrow results. The requirements were planted by the same team that wrote the cue rules, n is small, and no GPT, Gemini or local model was tested. `coding_recall` ranks by distinct keywords matched with no index, no time filter and no fact-augmented keys. It cannot fetch the tool output behind an action, because that output was never stored.

## Tool I/O is the missing half of the record, and it is cheap to capture faithfully

Every major app now exposes tool results and file impact to a third party without the model's help. Claude Code has more than 30 hook events. **PreToolUse** gives `tool_name`, `tool_input` and `tool_use_id` before any side effect. **PostToolUse** adds the structured `tool_response` and `duration_ms`. **PostToolUseFailure** carries the error, and **PostToolBatch** carries the exact text the model saw. Hooks fire inside subagents with `agent_id`/`agent_type`, MCP calls carry `mcp_server {name, source}`, and **PostCompact** delivers the generated `compact_summary` ([CC hooks](https://code.claude.com/docs/en/hooks)). Claude Code's transcript `toolUseResult` for Edit and Write includes `originalFile` and `structuredPatch`. Bash results include `stdout`, `stderr` and `interrupted`. Subagents write their own JSONL under `subagents/`, and compaction leaves a `compact_boundary`. This comes from observed records of v2.1.299–303, because the format is undocumented ([CC .claude directory](https://code.claude.com/docs/en/claude-directory)). Codex now has Claude-Code-compatible hooks. Its rollout JSONL persists `exec_command_end` (`aggregated_output`, `exit_code`), `patch_apply_end.changes` (full content for add and delete, unified diff for update) and a per-turn `turn_diff` ([Codex hooks](https://developers.openai.com/codex/hooks); [protocol.rs](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs); [policy.rs](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/policy.rs)). Gemini CLI's AfterTool gives `tool_response {llmContent, returnDisplay, error}`, and its opt-in checkpointing commits a shadow-git snapshot before every approved file-modifying tool ([Gemini hooks](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md); [Gemini checkpointing](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/checkpointing.md)). Cursor provides `afterShellExecution.output`, `afterMCPExecution.result_json` and `postToolUseFailure`, but `afterFileEdit` gives only old/new string pairs ([Cursor hooks](https://cursor.com/docs/agent/hooks)). Cline, Roo, Aider, OpenHands and Continue mainly expose history files. Local models served through these IDEs add no capture surface of their own (same notes; [Roo](https://github.com/RooCodeInc/Roo-Code/blob/main/src/shared/globalFileNames.ts); [Aider](https://github.com/Aider-AI/aider/blob/main/aider/website/docs/config/options.md)).

| App | Pre-call intent | Result in real time | Before/after file content | Gaps a capture layer must close |
|---|---|---|---|---|
| Claude Code | PreToolUse | PostToolUse / Failure / Batch | transcript `originalFile` + `structuredPatch`; `file-history/` | Bash side effects (`bashEditDiff` is beta, git-only, mode-gated); cancel fires no failure hook |
| Codex CLI | PreToolUse | PostToolUse (no failure event) | rollout `patch_apply_end`, `turn_diff` | hosted tools (WebSearch) bypass hooks |
| Gemini CLI | BeforeTool | AfterTool | shadow-git checkpoint (opt-in) | failure behaviour of AfterTool unverified |
| Cursor | preToolUse, beforeShell/MCP | postToolUse, afterShell, afterMCP | old/new strings only | must snapshot the before-image itself |

Three gaps matter for Continuum's invariants. First, **vendor file tracking is partial.** Claude Code checkpointing "does not track files modified by Bash commands", external changes or concurrent sessions, and is "not a replacement for version control" ([CC checkpointing](https://code.claude.com/docs/en/checkpointing)). A faithful impact record needs Continuum's own workspace fingerprint around write-capable calls. App diffs become corroborating evidence, not the source of truth. Second, **a PreToolUse with no matching Post event is exactly the "unknown outcome" case**. That happens on crash, kill or cancel, and cancellation explicitly fires no failure hook ([CC hooks](https://code.claude.com/docs/en/hooks)). Without PreToolUse capture, Continuum cannot know a call was attempted, so it cannot satisfy invariant 8 ("no new side-effecting action while an unknown effect remains unresolved") for coding sessions. Third, **no app guarantees hook ordering or exactly-once delivery.** Claude Code runs matching hooks in parallel, and Codex runs async hooks concurrently with cancellation at session end. Capture must deduplicate on `(app, app_session, tool_use_id, phase)` and order by app IDs and timestamps. Claude Code's 1.5 s SessionEnd default means hooks should append to a local spool and return (*inference from the cited limits*).

Cheap and faithful are compatible if storage separates identity from bulk. OpenTelemetry's GenAI conventions, still at Development stability, make `gen_ai.tool.call.arguments` and `gen_ai.tool.call.result` **opt-in and flagged as sensitive**. They allow `gen_ai.tool.call.id` only when the provider supplied it, and forbid fabricating a fallback ID ([OTel GenAI agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md)). That matches invariant 4: the app's `tool_use_id` is a correlation key, never operation identity. The inferred design keeps bounded, redacted arguments in the immutable event. Outputs go in a separate **content-addressed blob table** keyed by a per-person keyed hash. Events carry the hash, size, exit code and a short redacted head and tail. Retention and erasure can then delete a blob without mutating history *(inference; no primary source for the claim-check pattern was retrieved)*. The secrets constraint makes this mandatory, not optional. Claude Code's own docs warn that if "a command prints a credential, that value is written to" the plaintext transcript ([CC .claude directory](https://code.claude.com/docs/en/claude-directory)). Continuum's redactor admits that unknown secret formats get through ([MEMORY-ALGORITHM.md](../docs/MEMORY-ALGORITHM.md)). Full output bodies should therefore be opt-in per person or repository, with excerpts and hashes as the default. That decision is for the user to make, not something to infer.

Capturing impact pays off in measured ways. The Complexity Trap's finding that hiding failure signals lengthens trajectories, Manus's advice to keep wrong turns, and Zep's −17.7% on assistant-action recall all point the same way. The next model needs **which commands failed, with their error text, and which files changed, with diffs**, not prose about them. No study directly measures handoff success with versus without tool outputs in the packet. That is the most valuable experiment for Continuum to run.

## Memory quality is measured as QA accuracy, and no benchmark measures handoff

The field's metrics are LLM-judge QA accuracy split by ability, retrieval recall and NDCG against annotated evidence, FactScore for summary faithfulness, and cost: tokens, peak context, p50/p95 latency and dollars per task. LongMemEval's GPT-4o judge agrees with experts more than 97% of the time overall, but only 0.90–0.97 on abstention. Its separate recall metrics show where retrieval fails and where reading fails ([LongMemEval](https://arxiv.org/abs/2410.10813)). Knowledge-update and contradiction categories appear in LongMemEval, MemoryAgentBench and BEAM. Abstention appears as LongMemEval abstention questions and LoCoMo's adversarial set, where GPT-3.5-16K's F1 fell from 13.1 to **2.1** as context grew ([LoCoMo](https://arxiv.org/abs/2402.17753)). These metrics often disagree. LoCoMo's summary RAG had high recall but no QA gain, and Mem0's lexical and judge rankings diverge ([Mem0 paper](https://arxiv.org/abs/2504.19413)). Any single headline number is therefore unreliable.

**No public benchmark measures what Continuum promises**: requirements, decisions and action history surviving a move between models or apps. Coding results measure cross-task experience reuse (Exp-SWE-Agent; SWE-ContextBench's ~8-point oracle-summary gain), not within-task handoff ([Exp-SWE-Agent](https://dl.acm.org/doi/pdf/10.1145/3803437.3807663); [Sandelin](https://medium.com/@mrsandelin/the-first-controlled-benchmark-of-ai-memory-in-coding-agents-8e0bb776d39e)). Continuum's runtime owns ground truth, so most of its evaluation can be deterministic, without a judge. It should report seven metrics separately. (1) Planted-fact recall in the packet. (2) Update correctness: the superseded value is absent or marked. (3) Abstention: the receiving model does not claim an unresolved or unknown effect is done. (4) Faithfulness: every packet item resolves to source event IDs, and agent claims are never labelled as facts. (5) Action fidelity: every tool call, failure and file change in the fixture appears, with no duplicates, including the commit-then-drop and missing-Post-event cases. (6) Cost: packet tokens, capture latency, and storage per session. (7) Downstream resume success on hidden tests, measured across vendors (GPT, Gemini, a local model), with repeated runs and confidence intervals. LoCoMo's 5–30-point variance between harnesses shows why repeated runs matter. The existing MEMORY-QUALITY benchmark covers (1) and part of (7). It does not cover (2)–(5) for tool activity, because that activity is not captured.

## Vendors have not solved it because memory is a provenance and incentive problem

Vendor memory is written by the model from a mix of trusted and untrusted inputs, without recording what caused each write. That makes it an attack surface. Rehberger's SpAIware used indirect prompt injection to plant persistent ChatGPT memories that exfiltrated all later conversations. OpenAI closed the exfiltration channel, but "memory injection is not fixed" ([Embrace The Red](https://embracethered.com/blog/posts/2024/chatgpt-macos-app-persistent-data-exfiltration/)). MINJA poisoned shared agent memory through queries alone ([MINJA](https://arxiv.org/abs/2503.03704)). A 2026 follow-up reports more than 95% injection success under idealized conditions and calls defenses understudied ([arXiv 2601.05504](https://arxiv.org/html/2601.05504v1)). Implicit memory also erodes user control. Willison's "dossier" critique of ChatGPT's chat-history memory argues that "the entire game… is to carefully control their context" ([Simon Willison](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)). Anthropic's memory tool pushes safety onto the integrator: "these safeguards are your responsibility" ([Claude memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)).

The structure of the market reinforces this. Compaction is provider-bound: OpenAI's compaction item "is opaque and not intended to be human-interpretable" and must be passed back unmodified ([OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction)), so it cannot serve as a cross-vendor handoff medium. Context mutation has a direct price, since clearing "invalidates cached prompt prefixes" ([Claude context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)). Transcript formats are undocumented, and Codex says its format "isn't a stable interface" ([Codex hooks](https://developers.openai.com/codex/hooks)). Commercial incentives appear to favour lock-in over portable memory, though no source states this *(inference)*. No vendor has published a quantitative evaluation of its compaction or a postmortem on memory failures. Vendors have not failed to build something that works. They have each built single-vendor, model-written memory, and the neutral, provenance-first layer is left to third parties. That is Continuum's opening.

## Recommended architecture: widen deterministic capture first, add LLMs last

The design keeps Continuum's invariants intact and adds four layers. Every layer below the brief is append-only or a projection that can be rebuilt from it.

**Layer 1: capture adapters and a local spool.** One adapter takes Claude-Code-style hooks (Claude Code, Codex, Cursor) using per-app field maps. A second handles Gemini's BeforeTool/AfterTool names and `mcp_<server>_<tool>` naming. Transcript and rollout importers handle reconciliation and history-file apps. Hooks write a redacted envelope to an append-only local spool and exit in milliseconds. A drainer inserts into PostgreSQL idempotently, keyed by `(app, app_session_id, tool_use_id|message_id, phase)`. Transcript parsing stays structural and tolerant of unknown record types. It stops skipping sidechains and instead records them under their `agent_id`.

**Layer 2: the episodic ledger (`coding_events`, immutable).** New event types sit beside `ChatCaptured`:

| Event | Source | Holds |
|---|---|---|
| `ToolCallStarted` | PreToolUse / BeforeTool / transcript `tool_use` | tool, MCP server and source, skill, agent_id, redacted bounded args, app call ID (correlation only), workspace fingerprint if write-capable |
| `ToolCallFinished` | PostToolUse / Failure / AfterTool / rollout | status `ok`/`error`/`interrupted`, exit code, duration, output blob hash + redacted head/tail, model-visible size |
| `ToolCallUnresolved` | reconciler, not the model | a start with no finish after the session moved on, crashed or ended; outcome **unknown** |
| `FileImpactObserved` | Continuum's own fingerprint before/after, corroborated by `structuredPatch`, `patch_apply_end`, `bashEditDiff`, shadow-git | paths, created/deleted, diff blob hash, +/- lines, which evidence agreed |
| `SubagentRan` | SubagentStart/Stop, sidechain JSONL | type, model, prompt excerpt, handback report (claim), its own tool calls by reference |
| `CompactionObserved` | PreCompact/PostCompact, `compact_boundary` | trigger, token counts, `compact_summary` stored as an **agent claim** |
| `InstructionsLoaded` | hook | which rules files loaded, with content hash |

Outputs and diffs go to a `coding_blobs` table (keyed hash, size, media type, redaction version, retention class, person). It falls under the same row-level security and human-only erasure as the events. By default only excerpts are stored, and full bodies are opt-in. Fingerprinting costs about 165 ms on a 20k-file repo, so take it around write-capable calls only (Edit, Write, apply_patch, Bash, non-read-only MCP) and at turn end, not around reads.

**Layer 3: derived memory (projections that can be rebuilt, never authoritative).** The *Requirements* projection is today's ledger with explicit `superseded_by`, `valid_from`, authority and source spans. It is rendered as current or superseded, never side by side unlabelled. *Decisions* are agent choices extracted from both prose and actions, for example "switched from X to Y after test Z failed", labelled as claims. *Procedural* memory holds per-repo build and test commands that last exited 0 on a known fingerprint, plus failed approaches with their error excerpts. *Unresolved effects* lists open `ToolCallUnresolved` items. An **optional** LLM extractor may write `ClaimExtracted` events. Each records the model, prompt hash, input event IDs and spans, is used only as an extra recall key and as labelled claim candidates, is never promoted to a fact, and never supersedes a user requirement. Items derived from untrusted tool output (web fetch, MCP results, file contents) carry an `untrusted` authority and cannot enter the requirements ledger.

**Layer 4: the brief and recall.** Keep the deterministic brief, ordered for primacy and recency. It starts with Attention: unresolved unknown effects (block new side effects), failing checks, verified tasks that need re-verification, and current requirements. It ends with the latest user message and the next action, restated. Add a "Last failures" block with redacted error excerpts. The "what the agent did" section should list file changes with diff stats and blob IDs. Every line carries event IDs. Serialize deterministically with a stable prefix, and size the brief to the receiving model's budget, rejecting it if oversize. Upgrade `coding_recall` to PostgreSQL full-text search (a `tsvector` over events and blob excerpts, plus trigram for identifiers) with time-range filters, and add a read-only "show event/blob by ID" over the existing MCP inspection surface. Embeddings (pgvector) would need a DECISIONS.md entry and may conflict with the v1 "no vector DB" rule, so defer them until full-text recall is measured as insufficient.

The changes in priority order, with the strength of support for each:

| # | Change | Basis |
|---|---|---|
| 1 | Capture PreToolUse/PostToolUse/Failure with call-ID pairing, and emit `ToolCallUnresolved` for unpaired starts; block the brief's "next action" until resolved | **Evidence** for capture surfaces and the missing-failure-hook case ([CC hooks](https://code.claude.com/docs/en/hooks)); **inference** that this enforces invariant 8 for coding sessions |
| 2 | Record file impact with Continuum's own before/after fingerprint around write-capable calls; store diffs as blobs | **Evidence** that vendor tracking misses Bash changes ([CC checkpointing](https://code.claude.com/docs/en/checkpointing)); cost trade-off is **inference** |
| 3 | Store command and tool outputs as redacted, content-addressed blobs with head/tail excerpts; surface recent failures in the brief | **Evidence** that agents' own actions are poorly recalled and that hiding failures hurts ([Zep](https://arxiv.org/html/2501.13956v1); [Complexity Trap](https://arxiv.org/abs/2508.21433)); blob/erasure design is **inference** |
| 4 | Capture subagent sidechains and compaction summaries (as claims) instead of skipping them | **Evidence** for surfaces; Cognition's misread-subtask failure ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)) |
| 5 | Explicit supersession and authority on requirements; mark or omit superseded items | **Evidence** that contradiction handling is weakest and distractors cause hallucination ([BEAM](https://arxiv.org/abs/2510.27246); [Chroma](https://research.trychroma.com/context-rot)) |
| 6 | Indexed full-text recall with time filters and ID drill-down | **Evidence** for key and time expansion gains ([LongMemEval](https://arxiv.org/abs/2410.10813)); choosing FTS over vectors is **inference** |
| 7 | Extend evaluation with update, abstention, faithfulness and action-fidelity metrics, across GPT, Gemini and local models | **Evidence** that metrics diverge and that no handoff benchmark exists |
| 8 | Label untrusted-source content; never promote it to requirements | **Evidence** for memory poisoning ([MINJA](https://arxiv.org/abs/2503.03704); [SpAIware](https://embracethered.com/blog/posts/2024/chatgpt-macos-app-persistent-data-exfiltration/)) |

Per AGENTS.md, each schema or event change needs matching updates to docs/03, docs/04, MEMORY-ALGORITHM.md and CHANGELOG, and failing tests written first. The tests must include commit-then-drop (Post event lost after a write) and a lagging transcript (the transcript "may lag the in-memory conversation", [CC hooks](https://code.claude.com/docs/en/hooks)). Two decisions belong to the user before any code changes: the default storage of full tool output given the no-secrets rule, and whether a missing Post event should *block* the next agent's side effects or only warn.

## Conclusion

The research reverses the usual framing of agent memory. The hard part is not deciding what to remember, which is where vendors spend their LLM calls. The hard part is never losing what happened and always knowing who said it. Every independent benchmark punishes early abstraction, and every security result punishes memory without provenance. Both reward the shape Continuum already has: an immutable journal, runtime-observed facts, and claims kept apart from facts. Continuum's real deficit is narrower and easier to fix than adopting a memory framework. It records the conversation about the work while discarding the work itself: tool outputs, diffs, failures, subagents and unfinished calls.

One implication is new. Pairing pre-call and post-call events turns memory into safety. A coding handoff layer that sees a write begin and never sees it end can tell the next model, as a runtime fact rather than a guess, that an effect is unresolved. No vendor memory system offers this, and it is where Continuum's ledger discipline and the cross-app hook surfaces line up. The open empirical question is how much each added layer (tool outputs, diffs, supersession) improves resume success across vendors. No public benchmark answers it, so Continuum's own trials, extended to GPT, Gemini and a local model, would be the first evidence on it.
